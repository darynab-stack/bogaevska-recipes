# Рецептник

Сайт з рецептами, де можна швидко знайти, що приготувати.

Фронтенд: [bogaevska-recipes-frontend](https://github.com/darynab-stack/bogaevska-recipes-frontend)

## Про проєкт

Тут зібрані рецепти з різних кухонь світу. Рецепт можна знайти за назвою або за продуктом, який є вдома. Список можна відфільтрувати за кухнею, типом страви, складністю і часом приготування, а ще відсортувати за назвою, часом приготування чи датою додавання.

На сторінці рецепта є фото, опис, інгредієнти з кількістю, кроки приготування, час і кількість порцій.

Що ще є на сайті:

- сторінки кухонь, де видно всі рецепти цієї кухні
- сторінки авторів з короткою інформацією про автора і всіма його рецептами
- реєстрація і вхід
- профіль з даними про себе
- улюблені, куди можна зберегти рецепт, щоб потім не шукати
- відгуки з оцінкою від 1 до 5
- сторінка «Про нас» з контактами

Переглядати рецепти, кухні й авторів може будь-хто. Додавати і змінювати їх можуть лише користувачі, які увійшли в акаунт, а видаляти лише адміністратори.

## Як запустити проєкт

Потрібен Python 3.12.

1. Склонуйте репозиторій і перейдіть у папку проєкту:

   ```bash
   git clone https://github.com/darynab-stack/bogaevska-recipes.git
   cd bogaevska-recipes
   ```

2. Створіть і активуйте віртуальне оточення:

   ```bash
   py -3.12 -m venv .venv
   source .venv/Scripts/activate
   ```

   На Linux або macOS: `python3 -m venv .venv` і `source .venv/bin/activate`.

3. Встановіть залежності:

   ```bash
   python -m pip install -r requirements.txt
   ```

   Для перевірок оформлення коду (`check_submission.py`) також потрібен `requirements-dev.txt`.

4. Створіть базу даних:

   ```bash
   python manage.py migrate
   ```

5. Створіть адміністратора. Він потрібен, щоб видаляти рецепти, кухні й авторів:

   ```bash
   python manage.py createsuperuser
   ```

6. Запустіть сервер:

   ```bash
   python manage.py runserver
   ```

   API буде доступне на `http://127.0.0.1:8000/api/`.

### Postman

Колекція з усіма запитами лежить у `postman/recipes.postman_collection.json`. Її можна імпортувати в Postman (Import) і запустити цілком (Run).

Перед запуском відкрийте змінні колекції (вкладка Variables) і вкажіть `admin_username` і `admin_password` свого адміністратора з кроку 5.

Що варто знати про колекцію:

- Базова адреса задана у змінній `{{base_url}}`, за замовчуванням `http://127.0.0.1:8000/api`.
- Папки запускаються по черзі, від 0 до 4. Папка 0 реєструє нового тестового користувача, входить в акаунт і сама зберігає токени у змінні `{{access_token}}` і `{{refresh_token}}`. Інші запити беруть токен звідти автоматично.
- Запити з видалення в папці 4 використовують токен адміністратора `{{admin_access_token}}`.
- Остання папка видаляє все, що створили попередні, тому колекцію можна запускати багато разів.

### Фронтенд

Фронтенд лежить в окремому репозиторії і запускається через Live Server на `http://127.0.0.1:5500`. Бекенд дозволяє запити з `http://127.0.0.1:5500` і `http://localhost:5500` (налаштування `CORS_ALLOWED_ORIGINS` у `config/settings.py`).

## Загальні правила

- Усі адреси починаються з `/api/` і закінчуються слешем, наприклад `/api/recipes/` і `/api/recipes/1/`.
- Дані передаються і повертаються у форматі JSON.
- Зв'язки з іншими об'єктами передаються як `id`, наприклад `"cuisine": 1`.
- Сторінка «Про нас» статична, тому окремого ендпоінта для неї немає.

Які статус-коди повертає сервер:

| Код | Значення |
|---|---|
| `200 OK` | все добре, у відповіді є дані |
| `201 Created` | щось нове створено |
| `204 No Content` | все добре, але у відповіді нічого немає (після видалення) |
| `400 Bad Request` | у запиті щось не так, наприклад не заповнене обов'язкове поле |
| `401 Unauthorized` | користувач не увійшов: токена немає, він недійсний або закінчився |
| `403 Forbidden` | користувач увійшов, але в нього немає прав на цю дію |
| `404 Not Found` | з таким id нічого немає |
| `409 Conflict` | дію не можна виконати через інші дані, наприклад видалити кухню, в якій є рецепти |

## Авторизація і права доступу

Для входу використовуються JWT токени (бібліотека `djangorestframework-simplejwt`).

Після входу (`POST /api/auth/login/`) користувач отримує два токени:

| Токен | Скільки живе | Для чого |
|---|---|---|
| `access` | 5 хвилин | передається в кожному запиті, якому потрібен вхід |
| `refresh` | 1 день | лише для того, щоб отримати новий `access` на `POST /api/auth/refresh/` |

### Як передавати токен

Access токен передається в заголовку `Authorization` зі словом `Bearer` перед ним:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

Коли access токен закінчився, сервер повертає `401`. Тоді треба відправити refresh токен на `POST /api/auth/refresh/`, отримати новий access і повторити запит.

### Вихід

Окремого ендпоінта для виходу немає. Щоб вийти, клієнт просто видаляє в себе збережені access і refresh токени. Сервер токени не зберігає, тому нічого видаляти на сервері не потрібно.

### Хто що може

| Дія | Гість | Користувач, який увійшов | Адміністратор (`is_staff`) |
|---|---|---|---|
| Переглядати рецепти, кухні й авторів (`GET`) | так | так | так |
| Додавати і змінювати (`POST`, `PATCH`) | ні, `401` | так | так |
| Видаляти (`DELETE`) | ні, `401` | ні, `403` | так |
| Дивитися свій профіль (`GET /api/users/me/`) | ні, `401` | так | так |

Адміністратора можна створити командою `python manage.py createsuperuser`.

## Формат помилок

Усі помилки мають однаковий вигляд:

```json
{
  "detail": "Пояснення, що сталося і що зробити",
  "errors": {}
}
```

- `detail` є завжди.
- `errors` містить помилки по конкретних полях, якщо дані не пройшли перевірку. В інших випадках це порожній об'єкт.

Приклад для `400`, коли не вказана назва кухні:

```json
{
  "detail": "Дані не пройшли перевірку. Виправте поля з помилками.",
  "errors": {
    "name": ["Це поле обов'язкове."]
  }
}
```

Приклад для `401`, коли запит без токена:

```json
{
  "detail": "Потрібно увійти в акаунт. Передайте access токен у заголовку Authorization: Bearer <токен>.",
  "errors": {}
}
```

Приклад для `403`, коли звичайний користувач видаляє рецепт:

```json
{
  "detail": "Видаляти можуть лише адміністратори.",
  "errors": {}
}
```

Приклад для `404`:

```json
{
  "detail": "Об'єкт з таким id не знайдено.",
  "errors": {}
}
```

Приклад для `409`, коли видаляють кухню з рецептами:

```json
{
  "detail": "Неможливо видалити кухню, бо в ній є рецепти (3). Спершу видаліть їх або перенесіть в іншу кухню.",
  "errors": {}
}
```

## Користувачі

### Реєстрація

Доступно всім.

`POST /api/auth/register/`

Тіло запиту:

```json
{
  "username": "maria_k",
  "first_name": "Марія",
  "last_name": "Коваленко",
  "email": "maria@example.com",
  "password": "Recepty2026!",
  "password_confirm": "Recepty2026!"
}
```

| Поле | Обов'язкове | Обмеження |
|---|---|---|
| `username` | так | до 150 символів, лише літери, цифри і `@ . + - _`, має бути унікальним |
| `first_name` | ні | до 150 символів |
| `last_name` | ні | до 150 символів |
| `email` | так | до 254 символів, коректний формат `name@example.com`, має бути унікальним |
| `password` | так | до 128 символів, мінімум 8 символів, не надто схожий на username чи email, не з переліку поширених паролів, не лише з цифр |
| `password_confirm` | так | має збігатися з `password` |

Пароль зберігається в базі лише у захешованому вигляді.

Відповідь: `201 Created`. Пароля у відповіді немає.

```json
{
  "id": 12,
  "username": "maria_k",
  "first_name": "Марія",
  "last_name": "Коваленко",
  "email": "maria@example.com"
}
```

Помилки: `400`, якщо дані не пройшли перевірку. Приклад:

```json
{
  "detail": "Дані не пройшли перевірку. Виправте поля з помилками.",
  "errors": {
    "email": ["Введіть коректну адресу електронної пошти."],
    "password": ["Пароль занадто поширений.", "Цей пароль повністю складається із цифр."]
  }
}
```

### Вхід

Доступно всім.

`POST /api/auth/login/`

Тіло запиту:

```json
{
  "username": "maria_k",
  "password": "Recepty2026!"
}
```

Відповідь: `200 OK`

```json
{
  "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

Помилки:
- `400`, якщо не вказані `username` або `password`
- `401`, якщо ім'я або пароль неправильні

### Оновити access токен

Доступно всім.

`POST /api/auth/refresh/`

Тіло запиту:

```json
{
  "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

Відповідь: `200 OK`

```json
{
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

Помилки:
- `400`, якщо не вказаний `refresh`
- `401`, якщо refresh токен недійсний або закінчився. Тоді треба увійти знову.

### Мій профіль

Потрібен access токен.

`GET /api/users/me/`

Заголовки:

```
Authorization: Bearer <access токен>
```

Відповідь: `200 OK`

```json
{
  "id": 12,
  "username": "maria_k",
  "first_name": "Марія",
  "last_name": "Коваленко",
  "email": "maria@example.com",
  "is_staff": false
}
```

`is_staff` показує, чи користувач адміністратор.

Помилки: `401`, якщо токена немає, він недійсний або закінчився.

## Рецепти

### Отримати список рецептів

Використовується на головній сторінці. Доступно всім.

`GET /api/recipes/`

Параметри запиту (усі необов'язкові):

| Параметр | Опис | Приклад |
|---|---|---|
| `search` | пошук за назвою | `search=борщ` |
| `ingredient` | пошук за інгредієнтом | `ingredient=гарбуз` |
| `cuisine` | id кухні | `cuisine=1` |
| `meal_type` | тип страви: `breakfast`, `soup`, `main`, `salad`, `dessert`, `drink` | `meal_type=soup` |
| `difficulty` | складність: `easy`, `medium`, `hard` | `difficulty=easy` |
| `max_time` | максимальний час приготування в хвилинах | `max_time=30` |
| `sort` | сортування: `title` (за назвою), `time` (спочатку найшвидші), `newest` (спочатку нові) | `sort=time` |

Приклад: `GET /api/recipes/?search=борщ&cuisine=1&sort=time`

Відповідь: `200 OK`

```json
[
  {
    "id": 1,
    "title": "Український борщ",
    "image": "https://example.com/borshch.jpg",
    "cuisine": 1,
    "meal_type": "soup",
    "difficulty": "medium",
    "cooking_time": 90
  }
]
```

Помилки: `400`, якщо `cuisine` або `max_time` не число, або `sort` має невідоме значення.

### Отримати один рецепт

Використовується на сторінці рецепта. Доступно всім.

`GET /api/recipes/{id}/`

Відповідь: `200 OK`

```json
{
  "id": 1,
  "title": "Український борщ",
  "description": "Класичний борщ на яловичому бульйоні",
  "image": "https://example.com/borshch.jpg",
  "cuisine": 1,
  "author": 3,
  "meal_type": "soup",
  "difficulty": "medium",
  "cooking_time": 90,
  "servings": 6,
  "ingredients": [
    { "name": "Буряк", "amount": "2 шт" },
    { "name": "Капуста", "amount": "300 г" }
  ],
  "steps": [
    { "number": 1, "text": "Зварити бульйон" },
    { "number": 2, "text": "Натерти буряк і обсмажити з морквою" }
  ],
  "created_at": "2026-10-12T10:00:00Z"
}
```

Помилки: `404`, якщо рецепта не існує.

### Додати рецепт

Потрібен access токен у заголовку `Authorization: Bearer <токен>`.

`POST /api/recipes/`

Тіло запиту:

```json
{
  "title": "Український борщ",
  "description": "Класичний борщ на яловичому бульйоні",
  "image": "https://example.com/borshch.jpg",
  "cuisine": 1,
  "author": 3,
  "meal_type": "soup",
  "difficulty": "medium",
  "cooking_time": 90,
  "servings": 6,
  "ingredients": [
    { "name": "Буряк", "amount": "2 шт" }
  ],
  "steps": [
    { "number": 1, "text": "Зварити бульйон" }
  ]
}
```

`description` і `image` необов'язкові. `cooking_time` і `servings` мають бути не менше 1. У рецепті має бути хоча б один інгредієнт і хоча б один крок.

Відповідь: `201 Created`, у тілі створений рецепт (як у `GET /api/recipes/{id}/`).

Помилки:
- `400`, якщо не вистачає обов'язкових полів, значення не з дозволеного списку, немає інгредієнтів чи кроків, або кухні чи автора з таким id не існує
- `401`, якщо немає токена

### Інші ендпоінти рецептів

| Що робить | Запит | Хто може | Тіло запиту | Відповідь | Помилки |
|---|---|---|---|---|---|
| Змінити рецепт | `PATCH /api/recipes/{id}/` | з токеном | тільки поля, які треба змінити, наприклад `{"cooking_time": 80}`. Якщо передати `ingredients` або `steps`, старий список повністю заміниться новим | `200`, оновлений рецепт | `400`, `401`, `404` |
| Видалити рецепт | `DELETE /api/recipes/{id}/` | адміністратор | немає | `204`, без тіла. Інгредієнти й кроки видаляються разом з рецептом | `401`, `403`, `404` |

## Кухні

Використовується на сторінці кухонь і у фільтрі на головній. Доступно всім.

`GET /api/cuisines/`

Відповідь: `200 OK`

```json
[
  {
    "id": 1,
    "name": "Українська",
    "description": "Борщ, вареники, голубці та інші страви",
    "image": "https://example.com/ukrainian.jpg"
  }
]
```

### Отримати одну кухню

Доступно всім.

`GET /api/cuisines/{id}/`

Відповідь: `200 OK`

```json
{
  "id": 1,
  "name": "Українська",
  "description": "Борщ, вареники, голубці та інші страви",
  "image": "https://example.com/ukrainian.jpg"
}
```

Помилки: `404`.

### Додати кухню

Потрібен access токен.

`POST /api/cuisines/`

Тіло запиту:

```json
{
  "name": "Українська",
  "description": "Борщ, вареники, голубці та інші страви",
  "image": "https://example.com/ukrainian.jpg"
}
```

Обов'язкова лише назва.

Відповідь: `201 Created`, у тілі створена кухня.

Помилки:
- `400`, якщо немає назви або кухня з такою назвою вже є
- `401`, якщо немає токена

### Інші ендпоінти кухонь

| Що робить | Запит | Хто може | Тіло запиту | Відповідь | Помилки |
|---|---|---|---|---|---|
| Рецепти кухні (на сторінці кухні) | `GET /api/cuisines/{id}/recipes/` | усі | немає | `200`, список рецептів як у `GET /api/recipes/` | `404` |
| Змінити кухню | `PATCH /api/cuisines/{id}/` | з токеном | тільки поля, які треба змінити | `200`, оновлена кухня | `400`, `401`, `404` |
| Видалити кухню | `DELETE /api/cuisines/{id}/` | адміністратор | немає | `204`, без тіла | `401`, `403`, `404`, `409`, якщо в кухні є рецепти |

Кухню, в якій є рецепти, видалити не можна. Спершу треба видалити ці рецепти або перенести їх в іншу кухню.

## Автори

### Отримати список авторів

Доступно всім.

`GET /api/authors/`

Відповідь: `200 OK`

```json
[
  {
    "id": 3,
    "name": "Олена Коваль",
    "bio": "Кулінарка, готує домашні українські страви",
    "photo": "https://example.com/olena.jpg"
  }
]
```

### Отримати одного автора

Доступно всім.

`GET /api/authors/{id}/`

Відповідь: `200 OK`

```json
{
  "id": 3,
  "name": "Олена Коваль",
  "bio": "Кулінарка, готує домашні українські страви",
  "photo": "https://example.com/olena.jpg"
}
```

Помилки: `404`.

### Додати автора

Потрібен access токен.

`POST /api/authors/`

Тіло запиту:

```json
{
  "name": "Олена Коваль",
  "bio": "Кулінарка, готує домашні українські страви",
  "photo": "https://example.com/olena.jpg"
}
```

Обов'язкове лише ім'я.

Відповідь: `201 Created`, у тілі створений автор.

Помилки:
- `400`, якщо немає імені
- `401`, якщо немає токена

### Інші ендпоінти авторів

| Що робить | Запит | Хто може | Тіло запиту | Відповідь | Помилки |
|---|---|---|---|---|---|
| Рецепти автора (на сторінці автора) | `GET /api/authors/{id}/recipes/` | усі | немає | `200`, список рецептів як у `GET /api/recipes/` | `404` |
| Змінити автора | `PATCH /api/authors/{id}/` | з токеном | тільки поля, які треба змінити | `200`, оновлений автор | `400`, `401`, `404` |
| Видалити автора | `DELETE /api/authors/{id}/` | адміністратор | немає | `204`, без тіла | `401`, `403`, `404`, `409`, якщо за автором закріплені рецепти |

Автора, за яким закріплені рецепти, видалити не можна. Спершу треба видалити ці рецепти або призначити їм іншого автора.
